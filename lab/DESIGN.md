# INLAvanilla design decisions

Decisions agreed after `IDEA.md` was written. Where the two disagree, this file wins.

## Settled

- **One `logpost`.** The user supplies `logpost(theta, ...)` returning log p(y, θ). There is no `loglik` / `logprior` split. The log marginal likelihood is valid only when `logpost` includes every normalising constant, and the docs must say so.
- **Pure R.** No Rcpp and no `src/`. Users bring compiled code by passing any R-callable function, e.g. `Rcpp::cppFunction()`, TMB's `obj$fn` / `obj$gr` (negate them: TMB minimises), RTMB, or BridgeStan.
- **No numDeriv, no sn.** Port INLAvaan's own finite differences (`fast_grad`, `fast_jacobian`, `fast_hessian`, now `fd_*` with per-coordinate steps) and skew-normal code (`fit_skew_normal`, `dsnorm`, `psnorm`, `qsnorm_fast`, `owen_t`). Imports are limited to base packages (stats, graphics, utils) plus cli.
- **v1 has no transform layer.** `logpost` is written on the unconstrained scale ϑ ∈ ℝᵐ. Including any Jacobian is the user's job: a prior on σ with ϑ = log σ needs `+ theta["log_sigma"]`. The docs must stress this, because forgetting it gives the wrong posterior, not merely a worse approximation. `summary()` reports on the ϑ scale. Natural-scale or derived quantities, such as σ, Σ, or continuous-time SEM drift matrices, come from `sampling(fit, fun = ...)`, and the user summarises the draws. `summary()` takes no `fun` argument for now. Copula draws never call `logpost`, so `nsamp` can be large at almost no cost. The reason for this choice: real constraints are often joint and model-specific (covariance matrices, stable drift matrices), and no generic transform layer can express them.
- **S3, not S7.** S4 and R6 are ruled out. The fit is a classed list built by one internal constructor, `new_inla_vanilla()`. `summary()` returns a `summary.inla_vanilla` object with its own `print()` method. S7 would add an Imports entry and an `@` workaround for R < 4.3, for features we don't use (validated properties, inheritance, multiple dispatch).
- **cli is a required Imports entry.** It is used for formatted messages, warnings and errors (`cli_abort()` etc.) and for progress bars and steps, as in INLAvaan. It may be dropped at a later optimisation stage, but not before. Add it to `DESCRIPTION` with the first code that uses it, to avoid an unused-Imports NOTE.
- **VB mean correction on by default.** It feeds the log marginal likelihood (+½ δᵀHδ, as in INLAvaan) and LOO/WAIC. It is also a diagnostic of the skew-normal fit, because skew-normal means should agree with ϑ̃ (Prop. 3.4). In INLAvaan the skew-normal scan is centred at the mode ϑ*, so the VB shift does not move the marginals themselves.
- **Stages 2 and 3 are independent switches** (agreed after v0.1.0): `vb = TRUE` and `marginals = c("skewnormal", "gaussian")`. They are not a ladder: the skew-normal scans are centred at the mode, so VB never moves them, and skew-normal without VB skips the VB stage's cost, at most (m + 1)(m + 2) + 1 gradient calls per sweep with a gradient, or (m + 1)(m + 2) log-posterior calls without one (see the VB expectation below). `vb = FALSE, marginals = "gaussian"` is the Laplace approximation alone; `marginals = "gaussian"` alone is the VB-centred Gaussian. The value may be abbreviated (`"skew"`, `"gauss"`), as with `match.arg()`. Gaussian marginals are stored as skew-normals with α = 0, so every method works unchanged, and `sampling()` then draws from the joint Gaussian exactly.
- **Three output levels, `verbose = FALSE` and `silent = FALSE` by default** (agreed after v0.1.0: `verbose` is a full diagnostic of the fit, and `silent` silences everything, for simulations). The default is the old `verbose = TRUE` output, one line per stage, and must stay as fast. Progress bars respect the user's `cli.progress_show_after` (0.5 s when unset); rendered documents keep them out through options in their setup chunk, as INLAvaan's README does, rather than through a terminal check in the package. `verbose = TRUE` adds grey detail lines under each stage, from what the fit has already computed (no extra calls): nlminb's message, iterations and evaluations and whether it was restarted, the whitened gradient and the Newton step at the mode, how the Hessian was taken, the largest correlation, the smallest eigenvalue of the correlation matrix and the Hessian condition number, the VB steps per iteration, Anderson and fallback use, a table of the marginal diagnostics (scan-end mass included) with the `summary()` flags marked, and the calls per stage. nlminb's own trace stays with `control = list(nlminb = list(trace = 1))`. `silent = TRUE` prints nothing and muffles every warning and message raised during the fit, including those of `logpost` and `grad`; errors still stop it. Both `TRUE` is an error. Whatever the level, each distinct warning is recorded as plain text in `fit$warnings`, and the fit stores `verbose` and `silent`, so later methods (`loo()` and `waic()`) can follow `fit$silent`.
- **Diagnostics match INLAvaan's** (owner's decision after v0.1.0: "where possible similar between both"). One function, `diagnostics_internal()` (`R/diagnostics.R`), computes INLAvaan's global and per-parameter diagnostics from the stored parts of the fit; the fit-time warning, the exported `diagnostics()` and, through `check_flags()` (`R/methods.R`), the flags of `print()` and `summary()` all read it, so they cannot disagree.
  - **Fit-time warning.** One `inlavanilla_diagnostics_warning`, headed as INLAvaan's ("Fit diagnostics flagged N potential issue(s):"), with INLAvaan's bullets, words and order: the mode shift, NMAD, the scan-end mass, the VB shift and the Hessian condition number, with inlavanilla's heavy-tails bullet after the scan-end mass. NMAD, scan-end mass and tails list at most three parameters, worst first, with values to two decimals (INLAvaan's format, which can print a value just above a level as the level itself); the mode and VB bullets name the worst parameter. Parameter names never enter cli template text: each bullet has its own variables, referred to by index, because names can hold braces and the templates are filled lazily (commit 9d1ced2). The footer points to `diagnostics()` and the vignette.
  - **The mode.** INLAvaan's `mode_shift_sigma` = |(Σg)ⱼ|/sⱼ decides the warning, above 0.1 posterior SDs, and the ok/! of the Laplace stage line. It is scale-free and does not depend on the order of the parameters. The old separate warning on the whitened gradient (above 0.01) is gone; its nlminb hint is an "i" line under the mode bullet. The whitened gradient `grad_mode` still decides the 1e-3 restart and is shown by `verbose = TRUE`. INLAvaan's bullet for a non-zero `nlminb()` return code is not ported, because without a gradient nlminb reports false convergence at accurate modes; `diagnostics()` reports `converged` as INLAvaan defines it, documented as unused.
  - **Hessian condition number.** INLAvaan's `hess_cond` and its 1e8 level, but scale-free: the eigenvalue ratio of the posterior correlation matrix, i.e. the Hessian in posterior-SD units. INLAvaan's raw definition fires on healthy fits whose posterior SDs differ widely (SDs 1e-5 and 1e3 give 1e16).
  - **VB.** `vb_shift` is the raw shift and `vb_shift_sigma` the shift in posterior SDs, as in INLAvaan; `kld` = `vb_shift_sigma²/2` per parameter, and the joint ½δᵀHδ is `kld_global`. With `vb = FALSE` the VB columns and `sn_vs_vb` are NA, as INLAvaan leaves them. The VB fallback is only recorded, as in INLAvaan (no bullet, no flag, no "!" on the stage line): a forced fallback (`control$vb_maxit = 1`) on a healthy fit used to warn.
  - **`summary()`** flags every warned check at the warning's level (NMAD moved from 0.05 to 0.1, INLAvaan's only NMAD level), plus `ridge_bend` (0.25 nats) and `sn_vs_vb` (0.1), inlavanilla's own, with "above" and a value that is not finite flagged. Its flagged lines list every parameter, worst first, with values (no truncation: on PolDem a top three would hide `logv_x2`, which MCMC shows is badly off). The table has an End mass column, and there is a Hessian line for m > 1. `print()`'s count of flagged checks equals the "!" lines of `summary()`.
  - **`diagnostics(object, type = c("global", "param"))`**, an S3 generic. INLAvaan's names, order and print formats, followed by inlavanilla's own (`vb_fallback`, `sn_vs_vb_max`, `ridge_bend_max`, `n_heavy_tails`; `sn_vs_vb`, `gamma1`, `tails`, `ridge_bend`). Left out: `nsamp` (draws are on demand), `grad_num`/`grad_diff` (extra calls; a user `grad` is checked at `init` and by its Jacobian asymmetry instead, with separate warnings), `vb_mcse_*` (the cubature rule is deterministic).
  - **`plot(type = c("marg_pdf", "sn_fit", "sn_fit_log"))`**: INLAvaan's `visual_debug()` in base graphics, from the raw scan log-heights and each fit's `logC`, kept in `fit$scan` (no extra calls; `NULL` for Gaussian marginals).
  - **Levels and wording.** The mode-shift, NMAD, scan-end-mass, VB-shift and condition-number levels are INLAvaan's; tails, ridge bend and SN−VB are inlavanilla's own, and the docs say which is which, with INLAvaan's caveat that every level is a package default, not a calibrated cut-off. The ridge bend level is set from an accuracy target, a marginal SD 10% too small: 0.253 by the normal-mean formula 1 − √(1 − 3b/4) (`lab/bend-threshold.md`). It was 0.1 (a 3.8% target) until October 2026, when the cross-model check in `lab/bend-calibration.R` (51 parameters against grids and HMC) showed that 0.1 flagged errors of 3–5%, among them the intercept of the main vignette, no different from unflagged ones, while 0.25 flags every scan-path narrowing of 10% or more. A posterior SD in the diagnostics is the Laplace SD at the mode, as in INLAvaan. INLAvaan's "healthy range" of 1e-3 to 1e-2 for `scan_end_mass` is not restored: INLAvaan's docs do state it (with a source in a code comment), but its lower bound fails for healthy fits (an exact Gaussian gives 6.3e-5, the vignette's Poisson 3.8e-4, INLAvaan's own test about 2.5e-4), and the two PolDem marginals that are badly off (0.0031, 0.0019) sit inside it.
  - **Citations.** Jamil and Rue (2026a) use the VB shift (Section 3.1) and NMAD (Section 4.4) as fit diagnostics, the SN−VB agreement as an internal check (Section 5.1), and the linear CMP as a first-order approximation to a curved ridge (Section 3.2.1), the basis of `ridge_bend`; Section 4.4 also describes the boundary pile-up a skew-normal cannot capture. The mode shift, condition number and scan-end mass are INLAvaan's `diagnostics()`, not the paper's. INLAvaan's 1,046-fit Spearman calibration is not quoted; the docs cite the paper's Supplementary Material calibration instead.
- **Posterior draws use `sampling()` only**, matching INLAvaan's exported generic. There is no `draws()` alias, and no `sample()` method, since `base::sample` is not generic.
- **One method per stage**, keeping INLAvaan's defaults:
  - skew-normal marginals
  - `nlminb`
  - the `"shortcut"` volume correction
  - for the VB expectation, a degree-5 cubature rule built on a regular simplex (`vb_nodes()`: at most (m + 1)(m + 2) + 1 nodes on the principal axes of Ω, all within 3 SDs), replacing INLAvaan's Sobol points. With a gradient the expected gradient is the weighted mean of the gradient over the nodes, exact when the log-posterior is a degree-6 polynomial in whitened coordinates. Without one, Stein's identity, E[z f(μ + z)] = Ω E[∇f], gives it from `logpost` values at the same nodes, exact up to degree 4. Deterministic either way.
    - History: v0.1 used the fully symmetric degree-5 rule (2m² + 1 nodes), and without a gradient it applied that rule to forward-difference gradients, at (m + 1)(2m² + 1) calls per sweep. In `lab/vb-benchmark.R` that rule was the most accurate on every model tested, from 1 to 30 parameters: 10 to 150 times better than 64 Sobol points in 1–2D, and 0.016 against 0.058 SDs at m = 30.
    - October 2026. The owner set a budget: the VB stage should take at most 1.5–2× the mode-and-Hessian stage, with or without a gradient. The old rule was far over it, so it was replaced (`lab/vb-simplex-benchmark.R`, 11 models from m = 1 to 80):
      - Without a gradient the VB stage went from 1.0–3.8× that stage at m ≤ 3, 8–23× at m = 5–10 and 110–330× at m = 20–80, to 0.65–1.2× up to m = 10, 2.2× at m = 40 and 80, and 3–3.7× on the two near-separated logistic regressions, where the iteration falls back to nlminb(). The 39-parameter SEM of the Rcpp article went from 73× to 1.25×.
      - The error against exact VB went from 1e-4–0.035 SDs to 0.004–0.073 SDs (median 0.015). VB's own error against the posterior mean is 0.01–0.2 SDs on these models, and on balance the new VB means are as close to the posterior means as the old ones: closer on the larger logistic regressions, further on the near-separated ones. A log-gamma posterior with shape 0.5 shows the cost of exactness to degree 4 only: 0.10 SDs from exact VB without a gradient, against 0.03 with one.
      - With a gradient the simplex rule halves the calls at large m (2.0–5.1× to 1.8–3.4× at m = 5–10, 41–100× to 22–52× at m = 20–80) at the same accuracy (errors up to 0.038 against 0.035 SDs; in 2D Radon's seven-point rule is somewhat less accurate than the nine-point rule it replaces).
    - With a gradient the budget is still not met beyond about m = 5 (12× on the SEM), and the owner accepted that. Rules with O(m) nodes would meet it, such as 2m + 2 antithetic points with their covariance matched exactly (exact for degree-4 log-densities, positive weights, more accurate than the old rule at m = 80). They were rejected. Switching rule at some m makes results jump when a parameter is added. Any O(m) rule with positive weights puts its nodes about √(m + 1) SDs out, and in tests fits then aborted near support boundaries that the degree-5 rules survive. INLAvaan's 64 Sobol points were less accurate (0.10 SDs on the SEM) and still over budget at small m.
- **Not ported:**
  - the `asymgaus`, `marggaus` and `sampling` marginals
  - NORTA
  - the `ucminf` and `optim` optimisers
  - Gauss–Hermite VB
  - parallel cores
  - PPP and DIC

## Findings to discuss

- **Linear scan path at small n.** The skew-normal scan follows the conditional mode path (CMP) of the Laplace Gaussian, which is a straight line (Lemma 3.1). When another parameter's conditional mode bends along that path, the scanned heights are too low in the tails. A common case is a noise scale, where σ̂²(K) ∝ SSR(K) bends quadratically. The marginal then comes out too narrow, by a factor that shrinks as O(1/n).
  - Example: Michaelis–Menten on the treated `Puromycin` data (n = 12; parameters log Vm, log K, log σ).
  - Exact marginal SDs from a 3D grid: 0.0382 and 0.1537 for log Vm and log K.
  - Skew-normal: 0.0315 and 0.127, both about 18% too narrow. Laplace is the same.
  - A full Laplace marginal with exact conditional modes and conditional Hessians recovers 0.0383 and 0.1541. So the gap comes from the linear path, not from the skew-normal fit or the volume correction.
  - log σ itself is captured almost exactly: skew-normal mean 2.4733 against an exact 2.4734, while Laplace gives 2.3324.
  - The test suite found the same effect independently:
    - For the normal mean under a normal–inverse-gamma prior, the skew-normal SD is short by exactly √(2(aₙ − 1)/(2aₙ + 1)), a Gaussian against the true Student-t.
    - For the log scale of a Weibull model (n ≈ 15), both the skew-normal and Laplace SDs are about 11% too small, and a full Laplace marginal is within 0.1%.
  - Prototype remedies on Puromycin (`lab/scan-path-prototype.R`), SD error for log Vm and log K:

    | Scan | SD error |
    |---|---|
    | Current | −17.7% |
    | One Newton step towards the conditional mode (Laplace curvature) | −8.1% |
    | Three Newton steps | −5.7% |
    | Full Laplace: exact conditional mode and conditional log-determinant at each scan point | −1.0% |

    So the bent path accounts for about two thirds of the gap, and the linear volume correction for the rest.
  - **Decision.** Keep the CMP and the shortcut volume correction, which make the method fast. Document the limit in the Accuracy section of `?inla_vanilla`, and flag it with the cheap `ridge_bend` diagnostic (named `bend` until October 2026): two gradient calls per parameter, flagged above 0.25 nats (0.1 at first; see "Levels and wording").
  - The full-Laplace remedy is INLA's "Laplace strategy" for marginals. It needs a conditional optimisation and a conditional Hessian at each of the 21 scan points: about 21(m + 3) gradient calls per parameter, against 2m + 2 now, so roughly 10× the cost of the marginal stage. It is a change of method and needs a decision.
  - In this example the SN − VB diagnostic flagged log σ (0.13 SDs). That gap came from the VB mean being off, not the skew-normal, so the diagnostic is documented as "either may be off".

## Later

- **Heavy-tailed marginals on the SEM (known limitation, kept for now).** Recorded after v0.1.0 for future work. On the Political Democracy SEM of `vignettes/articles/rcpp.qmd` (39 parameters, n = 75), checked against HMC (4 chains of 10,000 draws, R-hat 1.000, tail ESS over 8,000; `lab/sem-hmc.R`) and against full Laplace marginals on a wide grid (`lab/sem-marginal-check.R`), which agree with each other:
  - `logv_x2` and `logv_dem65` are badly off. The skew-normal SD is 0.38 and 0.46 of the posterior SD, and the 2.5% quantile is −3.46 against −6.98 and −3.60 against −7.34 (2.4 and 2.0 posterior SDs). The upper quantiles agree. The data cannot keep these residual variances away from zero, so the log-density's left tail is linear with slope 0.50: the Gamma(1, 0.5) prior on the SD, with its Jacobian. No skew-normal can follow an exponential tail. On the variance scale the skew-normal overstates the mean by 16–18% and puts the 2.5% quantile at 0.03 instead of 0.001.
  - The other 37 parameters: SD ratios 0.93–1.00 (median 0.97), means within 0.08 posterior SDs, quantiles within 0.21. This is the straight-scan narrowing below.
  - On the natural scale (INLAvaan reports variances), against Stan NUTS on an independently written model (`lab/poldem.stan`, 4 × 10,000 draws, R-hat 1.00, no divergences): x2~~x2 mean 0.23 posterior SDs too high, SD ratio 0.85, 2.5% quantile 0.031 against 0.001; dem65~~dem65 mean 0.17 SDs too high, SD ratio 0.90. The other 37 natural-scale parameters: means within 0.09 SDs, SD ratios 0.93–1.01, quantiles within 0.28 SDs. So the error is large on the unconstrained scale that inlavanilla reports, and moderate on the natural scale that INLAvaan reports.
  - INLAvaan (0.3.2.9006, `asem(..., meanstructure = TRUE)`, default priors) gives the same marginals as inlavanilla to about 3 significant figures (x2~~x2 mean 0.1322 against 0.1323, 2.5% quantile 0.0314 against 0.0315), so matching INLAvaan does not rule this out; both share the limitation.
  - Diagnostics: `ridge_bend` is 0.11 and 0.44 for the two bad parameters, but its size does not rank how far off a marginal is: `logv_x2` (0.11) sits between `b` and `z_y2_y6`, 7% and 3% too narrow. Its old level, 0.1, flagged both by chance; since the level became 0.25 only `logv_dem65` is flagged, and no check flags `logv_x2`. A check aimed at the tail (below) is the fix, not a ridge bend level kept low. `tails` passes everywhere, because at ±4 Laplace SDs the drop is still over 3 nats: the tail flattens only further out.
  - An earlier comparison against full Laplace marginals on a ±4.5 SD grid gave "about 25% too narrow" for `logv_dem65`: the grid cut off the tail. Use a wide grid.
  - Decision (after the MCMC checks): this is the known boundary limitation of the skew-normal, documented in the INLAvaan manuscript, and smaller on the natural scale. inlavanilla matches INLAvaan here, which is what matters. Keep `tails`, NMAD and the VB checks; compute INLAvaan's `scan_end_mass` (here 0.0031 for `logv_x2` and 0.0019 for `logv_dem65`, the two largest). No further MCMC calibration.
  - Later the package owner left the use of the diagnostics to us ("fire warnings"), with a vignette explaining them: one fit-time `inlavanilla_diagnostics_warning` (`R/diagnostics.R`), `summary()` flags, and `vignettes/diagnostics.qmd` explaining every check. The owner then asked for the diagnostics to match INLAvaan's; see "Diagnostics match INLAvaan's" under Settled. Every document's fits stay silent.
  - Candidate fixes: a tail check from the slope of the scan at its ends (no extra calls), compared with the Gaussian slope; a wider or adaptive scan for flagged parameters; the full Laplace marginal on an adaptive grid for flagged parameters only (about 10 times the cost of the marginal stage); one Newton step towards the conditional mode at each scan point (halved the narrowing on Puromycin, `lab/scan-path-prototype.R`).
- **LOO/WAIC (added after v0.1.0, when the owner made it non-negotiable for model comparison).** INLAvaan's deterministic second-order Taylor LOO and WAIC (Alhyari, Jamil, Montcho and Rue, 2026, "Deterministic leave-one-cluster-out cross-validation for multilevel Bayesian models", arXiv:2609.00670 [stat.ME]; `R/loo.R` and `R/method-loo.R` in INLAvaan): per-unit score s_u and Hessian H_u of the pointwise log-likelihood at the VB mean, with the Laplace covariance Ω; log CPO_u = ℓ_u − ½ s_uᵀ(Ω⁻¹ + H_u)⁻¹ s_u + ½ log|I + ΩH_u|, lpd_u likewise with −H_u, p_waic,u = s_uᵀΩs_u + ½ tr[(H_uΩ)²]. No draws and no Monte Carlo error.
  - Interface: `loo(fit, loglik, ...)` and `waic(fit, loglik, ...)`, with `loglik(theta, ...)` returning one term per unit (per cluster for leave-one-cluster-out). The vignette `model-comparison` writes `loglik` and `logprior` separately and `logpost` as their sum.
  - Differences are taken in whitened coordinates, 0.01 SD apart: m² + m + 1 calls. If any unit's leverage k ≥ 1, everything falls back to first order with a warning, rather than mixing orders or dropping units.
  - Results are shaped like the loo package's objects, so `loo::loo_compare()` works with loo only in Suggests. The methods are registered on loo's generics too, and the default methods forward other objects to loo, so attaching inlavanilla after loo, rstan or brms does not break them.
  - The generics' first argument is `object`, so data named `x` reaches `loglik`; with loo attached later, loo's `loo(x, ...)` is called, which is documented.
  - `loo()` and `waic()` inherit `silent` from the fit (owner's decision), including the warnings of `loglik`, which are recorded in the result.
  - Checked in the vignette against 54 brute-force refits (warpbreaks, negative binomial). The sampling route still works: `loo::loo(sampling(fit, 4000, fun = loglik, ...))`.
- INLAvaan and inlavanilla both export `sampling` and `diagnostics`, so loading both masks one of them. If INLAvaan later uses inlavanilla as its engine, the generics should live here. `diagnostics.default()` passes an S4 object on to INLAvaan's `diagnostics()` when the INLAvaan namespace is loaded, as `loo.default()` does for loo; the other way round needs INLAvaan's S4 generic to gain a `useAsDefault`.
- **Transform layer, as a wrapper around the engine.** Given `transform`, build an unconstrained `logpost(ginv(ϑ)) + log|det J|` and its gradient, run the unchanged v1 engine, then post-process the summaries. Size-1 blocks map the skew-normal back analytically; joint blocks go through the draws. It would support:
  - named elementwise transforms (`"log"`, `"logit"`, `"tanh"`);
  - custom elementwise transforms `list(g, ginv)`;
  - joint blocks `list(pars, type = "cov")` or `list(pars, g, ginv)`, with log|det J| taken numerically when not supplied. A built-in `"cov"`/`"cor"` would follow INLAvaan: log sds plus atanh of (partial) correlations.

  A structured `init` such as `list(Sigma = diag(p))` could sit on top. None of this changes the engine.
- A TMB adaptor: with random effects, TMB's `fn` is already the Laplace-integrated π(y | ϑ).

## API sketch (v0.1)

```r
fit <- inla_vanilla(logpost, init, grad = NULL, ..., vb = TRUE,
                    marginals = c("skewnormal", "gaussian"), verbose = FALSE,
                    silent = FALSE, control = list())
fit; summary(fit); plot(fit)
sampling(fit, nsamp = 1000, fun = NULL)
```
